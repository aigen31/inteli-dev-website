# Бот настроек сайта

Отдельный Telegram-бот, через который владелец меняет состояние сайта с
телефона — в первую очередь **статус занятости** (тот блок, что виден в шапке,
на главной и в `/api/status`).

Это **не** тот бот, что присылает заявки: у него свой токен и нет прав ничего
менять. Бот заявок (`TELEGRAM_BOT_TOKEN`) остаётся каналом «только на запись».

---

## 1. Настройка (один раз)

### 1.1. Секреты в окружении

```bash
# .env (локально) или .env.prod (на сервере)
SETTINGS_BOT_TOKEN=8973210524:AA...          # токен от @BotFather
SETTINGS_BOT_ADMIN_ID=330711327              # ваш Telegram user id
SETTINGS_BOT_WEBHOOK_SECRET=$(openssl rand -hex 32)
```

Пока хотя бы одно из трёх значений пустое, `/api/settings-bot/webhook`
отвечает **404** и не принимает ничего. Это осознанный fail closed: без
секрета эндпоинт смог бы дёргать кто угодно и менять статус сайта.

Свой Telegram id можно узнать, просто написав боту: он ответит
`Доступ запрещён. Ваш Telegram ID: …`.

### 1.2. Регистрация вебхука

Telegram должен знать, куда присылать команды. Скрипт берёт токен и секрет из
того же файла окружения, что и приложение, поэтому они не могут разойтись.

```bash
# на сервере, откуда есть доступ к api.telegram.org
scripts/set-telegram-webhook.sh

# посмотреть текущее состояние / снять
scripts/set-telegram-webhook.sh --info
scripts/set-telegram-webhook.sh --delete
```

⚠️ **api.telegram.org недоступен из РФ без прокси.** С хоста разработки
(AS50022, Минусинск) он не отвечает — скрипт нужно запускать с прод-сервера
или через прокси. Проверить доступность:

```bash
curl -s -m 10 "https://api.telegram.org/bot${SETTINGS_BOT_TOKEN}/getMe"
```

Если сервер тоже не видит Telegram, бот не заработает ни через вебхук, ни
через long polling: приложению всё равно нужно *отвечать* на команды. Варианты —
прокси (`[settings_bot] api_base` + `HTTPS_PROXY`) или запуск на хосте с
доступом.

### 1.3. Перезапуск приложения

```bash
docker compose up -d --force-recreate web      # перечитать env
```

## 2. Команды

| Команда | Что делает |
|---|---|
| `/status` | Показать текущее состояние и кнопки |
| `/available` | Статус «приём заявок открыт» |
| `/busy` | Статус «приём заявок ограничен» |
| `/full` | Статус «приём заявок закрыт» |
| `/projects 3` | Сколько проектов в работе (0–99) |
| `/slot с 1 октября` | Ближайший свободный слот (до 120 символов) |
| `/when 1 октября` | Дата доступности (до 120 символов) |
| `/help` | Справка |

Плюс inline-кнопки: `Открыт` / `Ограничен` / `Закрыт` / `Обновить`.
Нажатие кнопки редактирует то же сообщение, а не плодит новые.

Команды понимаются и в форме `/status@bot_name` — так Telegram присылает их в
группах.

### Что видит владелец

```
Настройки сайта

Статус: Приём заявок: ограничен
Проектов в работе: 3
Ближайший слот: с 1 октября
Дата доступности: 2026-10-01

Обновлено: 24.09.2026 07:12 UTC

[ Открыт ] [ Ограничен ] [ Закрыт ]
[            Обновить              ]
```

## 3. Где изменение становится видно

Одна команда в Telegram → запись в SQLite → публикация в памяти процесса.
Дальше новые данные отдают все точки сразу, без рестарта:

| Место | Что меняется |
|---|---|
| Бейдж в шапке (все страницы) | подлежащее + состояние, цвет точки и текст подсказки |
| Главная, hero | `StatusBadge` |
| `GET /api/status`, `/api/status.json` | `status`, `label`, `icon_name`, `current_projects`, `next_free_slot`, `updated_at` |
| AI-чат, вопрос «Когда вы свободны?» | текст ответа |

Формулировки всех четырёх поверхностей берутся из одного словаря —
`services/status.rs::presentation`. Бейдж, чат, API и бот не могут разойтись по
словам: попытка ввести свои строки на любой из поверхностей ломает тест
`all_surfaces_share_one_vocabulary` / `bot_vocabulary_matches_the_status_dictionary`.

Пример проверки:

```bash
curl -s http://127.0.0.1:8282/api/status
curl -s http://127.0.0.1:8282/ | grep -o 'status-badge status-[a-z]*'
```

## 4. Почему статус живёт в SQLite, а не в OpenViking

OpenViking — источник правды для **контента**: кто я, что делаю, сколько стоит.
Статус занятости — это **состояние сервиса**: он меняется несколько раз в день
и должен переживать рестарт и записываться даже когда OpenViking недоступен.
Поэтому он хранится рядом с заявками (таблица `site_settings`, ключ → JSON) и
не требует сети.

`SiteContent.availability` из OpenViking остаётся **значением по умолчанию**:
им пользуются, пока в БД нет сохранённой записи.

Чтение при старте: `site_settings` → если пусто, `SiteContent`.

## 5. Безопасность

| Угроза | Защита |
|---|---|
| Кто-то нашёл бота и меняет статус | Проверка `from.id == admin_id`; остальным — отказ с их ID |
| Сторонний сервис дёргает вебхук | Заголовок `X-Telegram-Bot-Api-Secret-Token`, сравнение постоянного времени; иначе 404 |
| Секреты в git | Только env; в `config.toml` значения пустые |
| Инъекция HTML в сообщение | Всё, что вводит владелец, уходит через `escape_html` (parse_mode: HTML) |
| Подбор секрета по времени ответа | Побайтовое сравнение без раннего выхода |

Отдельно: эндпоинт **не заменяет** админку по токену. Изменения, которые
требуют пароля (`ADMIN_TOKEN`), через бота недоступны.

## 6. Как это устроено в коде

```
Telegram ──HTTPS──► POST /api/settings-bot/webhook
                         │  проверка X-Telegram-Bot-Api-Secret-Token
                         ▼
              SettingsBot::handle_update()          src/services/settings_bot.rs
                         │  from.id == admin_id?
                         ├── parse_update()   → Incoming      (чистая)
                         ├── parse_command()  → BotCommand    (чистая)
                         ├── apply_command()  → Applied       (чистая, вся валидация)
                         ▼
              settings::update_availability()        src/settings.rs
                         ├── storage::settings::save_availability()  → SQLite
                         └── SiteSettings::set_global()              → живое состояние
                         ▼
              sendMessage / editMessageText / answerCallbackQuery
```

Вся логика — чистые функции, сеть трогают только три метода отправки. Поэтому
поведение бота покрыто тестами без единого обращения к Telegram
(`api_base` подменяется на закрытый порт).

Разбор апдейтов, команд и переходов состояния — `src/services/settings_bot.rs`.
Хранилище — `src/storage/settings.rs`. Глобальное состояние —
`src/settings.rs`.

## 7. Тесты

**Юнит** (`src/services/settings_bot.rs`): сравнение секрета (включая пустой),
активность бота, разбор `message` и `callback_query`, игнорирование прочих
апдейтов, все команды и их аргументы, отказ на неизвестной команде, переходы
состояния, границы `projects` (0/99/-1/100), обрезка и лимит длины `slot`/`when`,
экранирование HTML, вёрстка состояния и клавиатуры.

**Интеграционные** (`tests/api.rs`): вебхук без секрета и с неверным секретом →
404, выключенный бот → 404, чужой пользователь → 200 без изменения статуса,
`/busy` меняет `/api/status`, `/projects` и `/slot`, отказ на невалидных
значениях, inline-callback, чат отдаёт живой статус, вопрос о занятости
сохраняется в историю.
