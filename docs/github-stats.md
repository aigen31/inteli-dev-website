# Статистика GitHub на главной («Открытый код»)

Блок на главной странице показывает публичную статистику профиля GitHub.
Данные забирает сервис `src/services/github.rs`, рисует `src/ui/github.rs`.

> **Ссылка на профиль в шапке.** Кроме блока, сайт показывает иконку GitHub в
> навигации (между ссылками и бейджем статуса) — она ведёт на
> `https://github.com/<username>`. Это **другой** механизм: адрес публикуется при
> старте из конфига (`github::set_profile`), а не берётся из снимка статистики,
> поэтому иконка не пропадает, когда GitHub недоступен, лимит API исчерпан или
> блок выключен через `enabled`. Прячется только пустым `username`.
>
> Иконка — официальный знак GitHub из Octicons (`BrandIcon`,
> `BRAND_ICON_PATHS`), а не Lucide: брендовые иконки из Lucide удалили.
> Регенерируется `scripts/update-icons.sh`. См. `RULES/ui-rules.md` → «Состав
> шапки».

## 1. Что нужно сделать на аккаунте GitHub

### Ничего — блок уже работает

Публичные данные (логин, аватар, число репозиториев, языки, контрибуции)
доступны анонимно. После деплоя блок появится сам, без токена и без
каких-либо действий в настройках аккаунта.

### Одна настройка, которая реально меняет цифру

**Приватные контрибуции.** По умолчанию коммиты в приватные репозитории не
попадают в публичный счётчик, а именно они обычно и составляют основную часть
работы.

> **Settings → Public profile** (напрямую:
> <https://github.com/settings/profile>) → блок **Contributions & Activity** →
> ☑ **Include private contributions on my profile** → **Update profile**

После этого публичный счётчик начнёт учитывать и приватные репозитории. Сами
репозитории и их содержимое при этом остаются приватными — наружу уходит
только факт и количество вкладов. Наш блок читает именно публичный счётчик,
поэтому эта галочка действует и без токена — и это единственная настройка,
которая реально меняет цифру в блоке.

### Опционально: Personal Access Token

Токен не обязателен. Он даёт две вещи:

1. **Лимит GitHub API: 60 → 5000 запросов в час.** Анонимный лимит считается
   на IP-адрес сервера и общий для всех, кто с него ходит. При TTL кэша 6 часов
   сервис тратит ~8 запросов в сутки, так что 60/час хватает с большим запасом —
   токен нужен, только если лимит начнёт исчерпываться (например, рядом на том
   же IP появится что-то ещё, дёргающее GitHub API).
2. **Контрибуции через GraphQL.** С токеном число берётся точным JSON-ответом,
   без токена — разбором HTML публичной страницы. Разбор надёжен (покрыт
   тестами), но HTML GitHub может измениться в любой момент; GraphQL стабилен.

**Как выпустить (classic PAT):** <https://github.com/settings/tokens>

> **Settings** → **Developer settings** → **Personal access tokens** →
> **Tokens (classic)** → **Generate new token (classic)**

- Note: `inteli-dev.ru stats`
- Expiration: как удобно (например, 1 год — потом перевыпустить)
- **Scopes: не отмечайте ни одного.** Для статистики публичного профиля и
  GraphQL `contributionsCollection` достаточно токена *без единого scope*.
  Не выдавайте `repo` и не давайте доступ к приватным репозиториям.

Fine-grained токены тоже подходят: достаточно доступа **read-only** к
публичным данным профиля (<https://github.com/settings/personal-access-tokens/new>).

**Куда положить:**

```bash
# локально (.env) или на сервере (.env.prod)
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

```bash
docker compose up -d --force-recreate web    # перечитать env
```

Также поддерживается `GITHUB_USERNAME` (перекрывает `username` из
`config.toml`); пустое значение игнорируется.

## 2. Конфигурация

```toml
[github]
username = "aigen31"          # пустая строка полностью выключает блок
enabled = true
cache_ttl_seconds = 21600     # 6 часов
show_stars = false            # звёзды и подписчики
```

| Ключ | По умолчанию | Смысл |
|------|--------------|-------|
| `username` | `aigen31` | Логин GitHub. Пустой → блок не рендерится. |
| `enabled` | `true` | Выключить блок, не удаляя логин. |
| `cache_ttl_seconds` | `21600` | Период фонового обновления снимка. |
| `show_stars` | `false` | Показывать плитки «звёзды» и «подписчики». |

### Почему звёзды и подписчики выключены

На момент внедрения у профиля 48 публичных репозиториев и 125 контрибуций за
год — это работает на репутацию. А звёзд 2 и подписчик 1: такие числа на
странице продаж читаются как «проекты никому не нужны» и вредят сильнее, чем
помогают. Флаг `show_stars = true` включает их одной строкой, когда числа
подрастут.

## 3. Как это устроено

```
GitHub API ──► GitHubService::fetch()  (раз в cache_ttl_seconds, в фоне)
                     │
                     ├─ REST /users/{u}          → логин, аватар, репозитории, подписчики, дата регистрации
                     ├─ REST /users/{u}/repos    → языки, звёзды
                     └─ GraphQL (с токеном) или
                        GET /users/{u}/contributions (без токена) → контрибуции
                     │
                     ▼
            GitHubStats::set_global()   ← глобальный снимок (RwLock<Option<..>>)
                     │
                     ▼
            GitHubStats::get()  → <GitHubStatsSection/>  (SSR, синхронно)
```

Страницы рендерятся на сервере и **синхронно**, поэтому тянуть GitHub из
компонента нельзя — это добавило бы сетевую задержку в каждый ответ. Вместо
этого `main.rs` запускает фоновую задачу: первый запрос сразу после старта,
дальше раз в TTL; при ошибке — повтор через 5 минут, чтобы разовый сетевой сбой
при деплое не оставлял страницу без блока до следующего перезапуска.

Тот же приём уже используется для `SiteContent` и `Limits`.

### Деградация

| Что сломалось | Что видит посетитель |
|---|---|
| GitHub недоступен целиком | Секции нет вообще |
| Не получены контрибуции | Плитки «контрибуции» нет, остальные на месте |
| `enabled = false` / пустой логин | Секции нет вообще |
| Репозиториев 0 | Секции нет (нечего показывать) |

Страница не ломается и не показывает нули ни в одном из случаев.

## 4. Проверка

```bash
# что отдаёт API анонимно (60 запросов/час на IP)
curl -s https://api.github.com/users/aigen31 | jq '{login,public_repos,followers}'

# счётчик контрибуций так, как его парсит сервис
curl -s -H 'User-Agent: Mozilla/5.0' \
  https://github.com/users/aigen31/contributions \
  | grep -o '[0-9,]* contributions in the last year'

# что реально отрисовалось
curl -s http://127.0.0.1:8282/ | grep -o 'Открытый код' | head -1
curl -s http://127.0.0.1:8282/ | grep -o 'github-[a-z-]*' | sort -u
```

Логи сервиса:

```bash
docker logs inteli-dev-web 2>&1 | grep -i github
# github: aigen31 — 48 репозиториев, 125 контрибуций
```

## 5. Если на продакшене блок не появился

Сервер `inteli-dev.ru` живёт на хосте в РФ, и `api.github.com` /`github.com`
могут быть недоступны с него. Проверка:

```bash
docker exec inteli-dev-web wget -qO- https://api.github.com/users/aigen31 | head
```

Если сети нет — вариант с внешним прокси (тогда в `base_url` сервиса нужно
добавить поддержку прокси) либо отказ от блока. Локально на этом хосте
`api.github.com` доступен, поэтому проверить прод-сеть стоит отдельно.

## 6. Тесты

`src/services/github.rs` — разбор контрибуций (включая `1 contribution` и
`1,234 contributions`), ранжирование языков, «Другие», проценты, дата
регистрации, цвета Linguist.

`src/ui/github.rs` — состав плиток и русская плюрализация, сокрытие
звёзд/подписчиков по флагу, рендер секции в HTML (`to_html()`): заголовок,
ссылка на профиль, `rel="noopener noreferrer nofollow"`, аватар с фиксированными
размерами, легенда языков; и что без снимка секция не рендерится вообще.
